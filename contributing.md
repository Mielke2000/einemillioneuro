# Beitrag zum Projekt

Danke, dass ihr an diesem Projekt mitarbeitet.

## Branching

- main: stabiler Branch
- feature/<name>: Features und Änderungen
- bugfix/<name>: Fehlerbehebungen
- hotfix/<name>: kritische Korrekturen

## Regeln

- Keine direkten Commits auf main
- Pull Requests sind Pflicht
- Jede Änderung braucht mindestens 1 Review
- Beschreibende Commit-Nachrichten
- Kleine und fokussierte PRs

## PR-Prozess

1. Branch erstellen
2. Änderungen umsetzen
3. Lokal testen
4. PR öffnen
5. Reviewer zuweisen
6. Änderungen anpassen
7. Merge nach Freigabe

## Code-Qualität

- Saubere, verständliche Namenskonventionen
- Keine ungetesteten Änderungen
- Keine unnötigen Änderungen im PR
- Dokumentation bei größeren Entscheidungen

## Tests

Vor dem Merge:
- lokale Verifikation durchführen
- funktionale Checks prüfen
- CI Status abwarten
